# Design-gap resolution

These normative contracts resolve the Major findings from the
[consolidated design review](../design_review/consolidated_review_report.md).
They extend the current design; the original reviewed snapshot and reports stay
unchanged. No application code is created by this resolution step.

The [parent design](../design_draft.md) identifies the applicable contracts:

- [Learning actions and correction replay](learning_contract.md)
- [HTTP schemas and errors](api_contract.md)
- [Adapter, fixtures, and class seed](fixture_contract.md)
- [PNG admission](media_contract.md)
- [Probe, phases, and live-gate timing](verification_contract.md)

The [resolution report](goldfish_review_report.md) maps each finding to its edit
and verification evidence. Original review artifacts remain in
[design_review](../design_review/README.md).

The [fresh re-audit](reaudit_report.md) preserves its findings as reviewed. The
resolution report records the subsequent repairs and local verification; it does
not overwrite the audit outcome or claim a second independent pass.
